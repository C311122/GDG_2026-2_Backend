# JPA N+1 문제와 해결 방법

## 1. N+1 문제란?

연관 관계가 설정된 엔티티를 조회할 때, **최초 조회 쿼리(1번)**로 가져온 **데이터 개수(N개)**만큼 연관된 하위 엔티티를 조회하는 **추가 쿼리(N번)**가 발생하는 성능 저하 현상입니다.

- **발생 예시 (주문 20건 조회 시):**
  1. 전체 주문 목록 조회: `SELECT * FROM orders` (**1번**)
  2. 각 주문의 주문 항목(`orderItems`) 지연 로딩 조회: `SELECT * FROM order_items WHERE order_id = ?` (**20번**)
  3. **총 실행 쿼리 수: 1 + 20 = 21번**

---

## 2. 해결 방법 ①: Fetch Join (페치 조인)

JPQL의 `join fetch`를 사용해 연관된 엔티티를 **처음부터 한 번의 SQL로 함께 조회**하는 방식입니다.

### 적용 코드

```java
@Query("""
    select distinct o
    from Order o
    left join fetch o.orderItems
    """)
List<Order> findAllWithItems();
```

- **실행 쿼리 수:** **1번** (`orders`와 `order_items`를 `JOIN`하여 한 번에 조회)
- **장점:** 쿼리 1번으로 모든 데이터를 가져오므로 조회 성능이 가장 뛰어납니다.
- **단점:**
  - 일대다(`1:N`) 컬렉션 페치 조인 시 데이터 뻥튀기가 발생하므로 `distinct` 처리가 필요합니다.
  - **페이징(`Pageable`) API를 함께 사용할 수 없습니다.** (메모리에서 페이징 처리되어 OOM 위험)

---

## 3. 해결 방법 ②: Batch Size (배치 사이즈 설정)

지연 로딩 시 연관 엔티티를 1건씩 조회하지 않고, **설정한 크기만큼 모아서 SQL의 `IN` 절로 한 번에 조회**하는 방식입니다.

### 적용 코드

- **방법 A. 전역 설정 (`application.yml`)**
  ```yaml
  spring:
    jpa:
      properties:
        hibernate:
          default_batch_fetch_size: 10
  ```
- **방법 B. 개별 엔티티 설정 (`Order.java`)**

  ```java
  @BatchSize(size = 10)
  @OneToMany(mappedBy = "order")
  private List<OrderItem> orderItems = new ArrayList<>();
  ```

- **실행 쿼리 수 (주문 20건, Batch Size 10 기준):** **3번**
  1. 전체 주문 조회 (**1번**)
  2. 주문 1~10번의 항목 묶음 조회 (`WHERE order_id IN (1, 2, ..., 10)`) (**1번**)
  3. 주문 11~20번의 항목 묶음 조회 (`WHERE order_id IN (11, 12, ..., 20)`) (**1번**)
- **장점:** 기존 `findAll()` 같은 기본 메서드를 수정하지 않아도 되며, **페이징 처리가 가능**합니다.
- **단점:** 데이터 건수에 따라 여러 번의 `IN` 쿼리가 나뉘어 실행됩니다.

---

## 4. 해결 방법 비교 요약

| 구분                        | N+1 발생 (기본) | Fetch Join                      | Batch Size (크기 10)                      |
| :-------------------------- | :-------------- | :------------------------------ | :---------------------------------------- |
| **주문 20건 기준 SQL 수**   | 21번 (1 + 20)   | **1번**                         | **3번** (1 + 20/10)                       |
| **페이징(`Pageable`) 지원** | 가능            | **불가능** (1:N 기준)           | **가능**                                  |
| **적합한 상황**             | 사용 지양       | 페이징 없는 단건/전체 상세 조회 | 페이징 목록 조회, 복잡한 다중 컬렉션 조회 |
